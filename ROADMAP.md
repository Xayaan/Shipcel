# Roadmap

What Shipcel does today, with each feature's status, is on [shipcel.com/features](https://shipcel.com/features/). This is what comes next, in order.

## Verify live first (built and tested, not yet run on a real account)

- The budget guard's pause on a real app (owner's click in the dashboard; the API refuses tokens by design).
- Worker Previews and Containers through Cloudflare's own builds, on a real repository (needs Cloudflare's GitHub app connected in the Cloudflare dashboard).

## Build next

1. ~~**Postgres and MySQL through Hyperdrive.**~~ Built on 28 October 2026: a connection string becomes a Hyperdrive configuration in your account (Manage → Database, or `shipcel hyperdrive add`), a `hyperdrive` binding in the Wrangler configuration deploys from GitHub or the terminal, previews bind the same database, and a "Postgres API" starter kit shows the pattern. Cloudflare hosts neither database; Hyperdrive pools and caches connections to one elsewhere (free: 100,000 queries a day; Workers Paid: unlimited). D1 stays the default. Not yet run against a real Postgres from shipcel.com.
2. ~~**Sign-in by email**~~ Built on 29 October 2026: one-time links sent through Cloudflare's Email Service from the app's own address (the sender's domain onboarded for Email Sending in the Cloudflare dashboard; Workers Paid: 3,000 emails a month included, then $0.35 per 1,000), and optional passwords set at the service's `/password/set` page. No third-party provider. Not yet run against a real onboarded domain.
3. ~~**OAuth for the MCP server**~~ Built on 29 October 2026: Shipcel is the authorization server for its own `/mcp` (metadata, dynamic client registration, PKCE, an approval page in the dashboard, a 90-day token per app, listed under API & CLI). Not yet tried from a real Claude.ai or ChatGPT connector.
4. ~~**OpenNext's cache for Next.js**~~ Built on 29 October 2026: OpenNext's incremental cache in R2 (or KV, or the app's own files), its Durable Object queue and tag cache, with the bindings each needs checked before a deploy; after each production deploy from the terminal or GitHub Actions, Shipcel fills the R2 bucket with the pages Next.js prerendered. The Next.js kit uses it. Not yet run against Cloudflare's R2. Still open: **branch previews for Next.js**, which wait on OpenNext adopting Cloudflare's `ctx.exports`, and **pull requests from forks**, which get no preview because a fork's code would build with the repository's token.
5. ~~**A container starter kit, and the first services**~~ Built on 29 October 2026: a Container app kit (a Worker on `@cloudflare/containers` in front of a container built from a Dockerfile), and Umami and n8n as services from their published images, with their data in a Postgres database hosted elsewhere and their secrets in the Worker; they deploy from GitHub with Cloudflare's builds, which `shipcel git connect` now chooses for containers, and the budget guard counts container CPU, memory and disk. Not yet run on Cloudflare. Still open: **one-click services** deployed by Shipcel without a repository (their images need no build, but Shipcel's Cloudflare sign-in has no Containers permission yet), and more of the catalog: Plausible needs ClickHouse, Ghost needs MySQL 8 and a storage adapter for uploads.
6. **WordPress**, started on 29 October 2026 as an experimental kit: the official image in a container, MySQL hosted elsewhere over TLS (Hyperdrive serves Workers, not containers), uploads kept in R2 and email sent through Cloudflare's Email Service by the Worker in front of WordPress, themes and plugins built into the image. Not yet run on Cloudflare; the proof checklist in [docs/runtime-matrix.md](docs/runtime-matrix.md) decides when it becomes a supported kit. Static exports and headless WordPress work today.
7. ~~**GitLab, Bitbucket and Gitea**~~ Built on 30 October 2026: `shipcel git connect` links a repository on any of them (and Forgejo) and writes its CI file; every push deploys through the host's own CI. GitLab.com jobs sign in with GitLab's ID token, so the repository holds no secret, and deploy production only from a protected branch; Bitbucket, Gitea and self-managed GitLab use a deploy token for one project (`shipcel tokens add --project`). Not yet run from a real pipeline. Containers still deploy from GitHub only.
8. ~~**Scheduled database backups to R2.**~~ Built on 30 October 2026: daily or weekly copies of a project's D1 database (Cloudflare's own SQL export) in an R2 bucket Shipcel makes in your account, the newest 1 to 90 kept and each downloadable from Manage → Database; up to 300 MB a copy through Cloudflare's API. Not yet run against a real account.
9. ~~**Telegram and email notifications**; shared variables across a workspace's projects.~~ Built on 30 October 2026: Manage → Notifications sends a project's events to a Telegram chat through the customer's own bot (Shipcel finds the chat from the bot's latest message) and to an email address once someone with that inbox confirms it, beside the webhook, through one outbox with retries; emails go through Cloudflare's Email Service from a sender the Shipcel owner sets up. **Shared variables** sets one secret on up to 20 of a workspace's projects at once, each as an operation in that project's history, and shows a project that missed a new value as out of date; Shipcel keeps names, never values. Not yet run against Telegram or a real sender domain.
10. ~~**Row-level security and data APIs**; database change streams.~~ Built on 30 October 2026: the sign-in service serves `/data/<table>` over the app's own D1 database for the tables the owner opens under Manage → Sign-in & realtime → Data API, each read and changed by everyone, signed-in users, or only the user in a row's owner column (row-level security), with PostgREST-style filters; every change is sent on realtime channels to those who may read the rows. REST only (no GraphQL); tested in workerd with D1 and Durable Objects, not yet run on Cloudflare.
11. **The CLI on npm**; ~~a Coolify comparison page~~. The comparison is at [shipcel.com/compare/coolify](https://shipcel.com/compare/coolify/) (built on 30 October 2026, from Coolify's pricing page and docs read that day). The CLI's package is ready for npm, where the name `shipcel` is free: its metadata, a pack of three files checked with `npm pack --dry-run`, and a publish workflow with provenance (`.github/workflows/publish-cli.yml`). Not published: it waits on the license below, a public repository (npm's provenance needs one), and a first publish by hand, after which trusted publishing takes over.
